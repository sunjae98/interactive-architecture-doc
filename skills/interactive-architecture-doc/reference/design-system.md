# 디자인 시스템 참고

`template.html`에 이미 구현돼 있는 CSS/구조 규칙 요약. 새 문서를 쓸 때 이 표를 보고
클래스를 고르면 되고, CSS 자체를 다시 설계할 필요는 없다.

## 색상 / 노드 타입 (`--client` `--decision` `--existing` `--new`)

| 클래스 | 기본 의미 | 색 | 언제 쓰나 |
|---|---|---|---|
| `.node.client` | 시스템 바깥의 클라이언트 | 핑크 계열 | 요청을 보내는 쪽, 최종 응답을 받는 쪽 |
| `.node.decision` | 판단이 일어나는 지점 | 보라 계열 | 분기가 갈리는 원인이 되는 로직/모델 |
| `.node.existing` | 이미 있는 것, 외부에서 처리 | 초록 계열 | 신규 개발이 필요 없는 부분 |
| `.node.new` | 이번에 새로 만드는 것 | 주황 계열 | 신규 개발이 필요한 부분 |

프로젝트 성격에 따라 이 네 범주의 실제 의미는 재정의해도 된다 (예: `existing`/`new` 대신
`sync`/`async`, `internal`/`external` 등). 다만 **재정의했다면 `.legend`에 반드시 그 의미를
명시**한다 — 색만 보고 유추하게 두지 않는다.

## 레이아웃 블록

| 클래스 | 역할 |
|---|---|
| `.stepper` | 문서 상단, 전체 단계를 가로로 나열하는 번호 목록 |
| `.legend` | 색상 범례 |
| `.board` | 본문 다이어그램 전체를 감싸는 중앙 정렬 컨테이너 |
| `.center-row` + `.node` | 다이어그램의 박스 하나 (가운데 정렬) |
| `.plain-arrow` | 박스 사이 세로 화살표(`↓`), `.arrow-label`로 화살표 옆 설명 텍스트 추가 가능 |
| `.internal` | "여기부터는 클라이언트가 모르는 내부 흐름"을 점선 박스로 표시. `.badge`로 라벨 |
| `.external-zone` | "여기부터는 시스템 완전히 바깥, 외부 시스템 영역"을 점선 박스로 표시. `.badge2`로 라벨 |
| `.fork-zone` + `.zone-overlay` (svg) | 분기가 일어나는 영역. 내부에 `.fork-row`를 두고, 판단
  화살표를 자동으로 그리는 SVG가 이 안에 오버레이된다 |
| `.fork-row` + `.fork-col` | 분기된 경로들을 나란히 배치 (기본 4열, 좁은 화면에서 자동 2열/1열) |
| `.external-row` + `.external-card` | 외부 시스템 목록을 카드로 나열 |
| `.tldr` | 문서 최상단 핵심 요약 박스 |
| `.callout` | 2단 카드 — 보통 "클라이언트가 보는 것" / "시스템이 떠안는 책임" 대비에 사용 |
| `.considerations` | 설계 검토·결정 사항 목록. 각 `<li>`에 `<span class="why">`로 근거 필수 |
| `.tool-examples` + `.tool-card` | API/함수 스키마 예시를 카드로 나열 |

## 노드 내부 구성 요소

- `.node .num` — 원형 단계 번호 배지 (`data-step`과 같은 숫자를 눈에 보이게 표시)
- `.node .tag` — 노드 상단의 작은 라벨 (예: "신규 — 서버 코드가 결정")
- `.node code` — 노드 안에 코드/페이로드를 보여줄 때. 어두운 배경 + 모노스페이스
- `.note` — 노드 하단의 회색 보충 설명
- `.detail-grid` / `.detail-left` / `.detail-right` / `.detail-item` — 노드 하나가 여러 하위
  결정(예: 모델 선택 방식 A vs B)을 함께 설명해야 할 때 좌우 2단으로 나눠 담는 레이아웃

## 상호작용에 필요한 data 속성

| 속성 | 위치 | 의미 |
|---|---|---|
| `data-step="N"` | `.node` | 이 노드가 전체 단계 중 몇 번째에 해당하는지. 플레이그라운드가 이 값으로 강조(`.active`) 대상을 고른다 |
| `data-branch="key1,key2"` | `.node` (선택) | 이 노드가 어느 시나리오에서만 등장하는지. 없으면 모든 시나리오 공통 |
| `data-fan-hub="hub-id"` | 분기의 원인이 되는 판단 노드 | 이 id를 가진 하나의 판단 지점에서 화살표가 부채꼴로 뻗어나감 |
| `data-fan-target="hub-id"` | 분기된 각 경로의 첫 노드 | 같은 `hub-id`를 가진 hub로부터 화살표를 받는 대상들 |
| `data-fan-svg` | `.fork-zone` 안의 `<svg>` | 그 zone 안의 화살표를 그릴 캔버스. zone마다 하나씩 필요 |

`.active` / `.altpath` 클래스는 JS가 런타임에 자동으로 붙였다 뗀다 — 직접 HTML에 쓰지 않는다.

## 반응형

- `.fork-row`, `.external-row`, `.callout`은 `900px~1180px` 이하에서 자동으로 열이 줄어든다
  (CSS에 이미 구현됨, 추가 작업 불필요)
- `.sidebar`(플레이그라운드)는 `1080px` 이하에서 sticky를 풀고 본문 위로 올라온다
